# StateSurface 2.0 — 수동 검증 체크리스트

작성일: 2026-10-14

상태: Draft — 구현 후 실행할 항목, 현재 미실행

요구사항은 [REQUIREMENTS.md](./REQUIREMENTS.md), 계약·결정·검증 ID는 [DESIGN.md](./DESIGN.md), 단계별 자동 테스트는
[IMPLEMENT.md](./IMPLEMENT.md)에 있다. 이 문서는 자동 테스트로 판정하기 어려운 항목을 사람이 실제 브라우저·장치·배포
환경에서 확인하는 **릴리스 판정용 체크리스트**다. 완료 보고가 아니라 구현 후 사용할 기준이다.

- 자동 테스트(Vitest·적합성 스위트·Playwright e2e·성능 게이트)가 통과한 뒤 실행한다. 이 문서는 그것을 대신하지 않는다.
- 전체 실행은 IMPLEMENT 단계 10이다. 각 항목의 "선행 실행" 단계가 끝나면 그 항목을 미리 실행해 결함을 일찍 찾는다.

## 1. 실행 조건

### 1.1 빌드와 환경

- production 빌드(`pnpm build` 후 어댑터별 실행)를 쓴다. 단, MT-16(개발 경험)은 dev 서버를 쓴다.
- 기본 배포는 Node 어댑터이며 MT-15는 5개 어댑터 전부를 쓴다. BASE_PATH 항목은 `BASE_PATH=/demo`로 다시 빌드한다.
- 결과마다 commit SHA, 어댑터, 브라우저·버전, 장치, 네트워크 조건, 경로를 기록한다(5장).
- cold cache(첫 방문)와 warm cache(반복 방문·반복 액션)를 구분한다.

### 1.2 브라우저·장치

| 구분      | 대상                                                  | 사용 항목                  |
| --------- | ----------------------------------------------------- | -------------------------- |
| 필수      | Chrome·Firefox·Safari 최신 안정판(데스크톱)           | 전 항목                    |
| 필수      | iOS Safari(실기기), Android Chrome(실기기, 중급 성능) | MT-02·07·08·09·10·13·14·17 |
| 보조      | Edge 최신                                             | MT-01·08·12                |
| 보조 기술 | VoiceOver(macOS·iOS), NVDA(Windows) + Firefox·Chrome  | MT-14                      |

브라우저마다 지원이 다른 기능(View Transition, `moveBefore`, Speculation Rules, `requestIdleCallback`)은 지원·미지원
양쪽 결과를 모두 기록한다. 미지원 쪽은 DESIGN이 정한 대체 동작이 통과 기준이다.

### 1.3 판정 규칙

- 각 체크 항목은 통과·실패·해당 없음 중 하나로 판정하고, 실패는 재현 절차와 증거(스크린샷·HAR·콘솔)를 남긴다.
- **릴리스 블로커**: 보안 결함, 데이터 유실(입력·로컬 상태가 조용히 사라짐), 오류로 기능이 동작하지 않음, 필수 브라우저에서
  주요 흐름 실패, DESIGN이 정한 대체 동작 실패.
- **비블로커**: 블로커가 아닌 시각·체감 결함. 담당자와 후속 이슈를 기록하면 릴리스할 수 있다.
- 모든 항목에 판정이 있고 블로커가 0이면 통과다(4장).

### 1.4 공통 준비물

- 데모 사이트(쇼케이스) production 빌드와 `create-state-surface` 최소·demo 생성 앱.
- 검증용 fixture 페이지: 라우터 없는 순수 static 페이지, GTM식 동적 주입 페이지(V-30), persist 대상(audio·iframe·입력이 있는
  위젯) 페이지, `server:defer` 개인화 슬롯 페이지, JS 없는 액션 폼 페이지. 자동 테스트와 같은 fixture를 쓴다.
- 브라우저 DevTools(Network·Console·Performance·Application), 네트워크 스로틀(Fast 4G·Offline), CPU 스로틀(4배).

## 2. 항목

### MT-01: 페이지별로 필요한 코드만 받는가

관련: V-01·V-05·V-06, NFR-01, DC-02·DC-04·DC-12. 선행 실행: 단계 3.

- [ ] 라우터·액션·boot·플러그인 없는 static fixture 페이지의 Network에 엔진 JS 요청이 없다. 앱 엔트리(`client/entry.ts`)가 있으면
      그 요청만 보인다.
- [ ] 홈·가이드·검색·채팅 각각에서 Lithent·아일랜드 청크는 아일랜드가 있는 페이지에서만, `client:load` 청크만 초기에(preload
      포함) 요청되고 `idle`·`visible`·`media` 청크는 조건이 충족된 뒤에 요청된다.
- [ ] 플러그인 청크(채팅 스크롤·목차 등)는 선언한 페이지에서만 요청된다. 디버그 오버레이는 `?debug=1`일 때만 요청된다.
- [ ] 페이지 소스와 client 청크를 열어 서버 전용 코드·비밀 값·DB 호출 흔적이 없음을 눈으로 확인한다(sentinel 자동 검사의 보완).
- [ ] `__SURFACE__`에 공개해도 되는 값만 있다(server 슬롯은 props 없음, 토큰·세션 값 없음).

통과 기준: 네 대표 페이지와 static fixture의 실제 요청 목록이 위 규칙과 일치한다.

### MT-02: 아일랜드 활성화와 입력 보존

관련: V-03·V-04·V-12, DC-04·DC-05. 선행 실행: 단계 5.

- [ ] CPU 4배·Fast 4G에서 `client:visible`·`client:idle` 아일랜드의 입력란에 활성화 전에 타이핑한다. 활성화 뒤에도 입력값·커서
      위치·포커스가 유지된다(필수 브라우저 전부).
- [ ] 활성화 전 첫 클릭은 재생되지 않고, 활성화 직후 두 번째 클릭부터 동작한다. `client:load` 아일랜드는 첫 클릭부터 동작한다.
- [ ] `client:only` 아일랜드는 fallback이 먼저 보이고 레이아웃 이동 없이 교체된다.
- [ ] DevTools에서 아일랜드 청크 요청을 차단하면 SSR 화면이 유지되고 1초 뒤 한 번 재요청하며, 그래도 실패하면 콘솔
      (전역 오류 핸들러)에 보고된다. 화면이 깨지지 않는다.
- [ ] 서버 갱신으로 같은 아일랜드의 props가 바뀌어도 입력 초안·토글이 유지되고, `resetKey` 값이 바뀌면 초기화된다.
- [ ] 같은 컴포넌트를 쓰는 아일랜드 두 개가 서로의 상태에 영향을 주지 않는다.

통과 기준: 입력 유실·포커스 튐이 없고 실패 시 DESIGN 5.2의 대체 동작이 보인다.

### MT-03: server 슬롯 갱신

관련: V-02·V-09, DC-03·DC-08·DC-10. 선행 실행: 단계 4.

- [ ] 검색 결과가 서버 HTML로 갱신되며 깜빡임이나 레이아웃 이동이 눈에 띄지 않는다.
- [ ] `swap="replace"` 슬롯 안에서 `id`가 있는 입력에 포커스를 둔 채 갱신하면 포커스·선택 범위·스크롤이 복원된다.
- [ ] `swap="morph"` 슬롯에서 입력 중인 값·펼친 `<details>`·재생 중인 미디어가 갱신 뒤에도 유지된다.
- [ ] server 슬롯 안 직접 지시자 아일랜드는 부모 교체 뒤 다시 활성화되어 동작한다(로컬 상태 초기화는 정상).
- [ ] UI 패치(클래스·CSS 변수)가 콘텐츠 갱신 뒤에 적용되고 `ui=null`이면 원래 모습으로 돌아간다.
- [ ] 슬롯 HTML에 넣은 `<script>`가 실행되지 않고 dev 콘솔에 경고가 나온다.

통과 기준: 갱신 결과가 같은 상태의 SSR과 같고 사용자 입력·포커스가 유실되지 않는다.

### MT-04: 액션·pending·동시성

관련: V-13, DC-11·DC-30·DC-31. 선행 실행: 단계 5.

- [ ] 버튼·폼 `data-action`과 `useAction` 버튼에서 pending 표시가 요청 완료까지 유지되고, 첫 결과 도착 표시(`data-has-result`)가
      스트림 중간에 바뀐다.
- [ ] 검색 스트림이 진행되는 동안 targets가 겹치지 않는 액션(좋아요 등)을 누르면 둘 다 끝까지 진행된다.
- [ ] 같은 검색을 빠르게 연속 실행하면 이전 요청만 취소되고 최종 결과는 마지막 입력 기준이다. 이전 요청의 종료가 새 pending을
      해제하지 않는다.
- [ ] targets를 선언하지 않은 액션을 실행하면 진행 중인 다른 요청이 취소되고 전체 슬롯에 pending이 표시되며, dev 콘솔에 targets
      선언 권장 경고가 한 번 나온다.
- [ ] `mode: 'queue'` 액션을 여러 번 누르면 순서대로 실행된다.
- [ ] `<Boot>`가 있는 페이지에서 클릭 없이 스트림이 시작되고, 조건이 거짓이면 실행되지 않는다.
- [ ] 서버 오류 시 오류 슬롯에 메시지가 보이고 다른 슬롯은 유지된다. 오류 슬롯이 없는 fixture에서는 화면 변화 없이 콘솔로
      보고된다.

통과 기준: 겹침 규칙대로만 취소되고 pending·오류 표시가 실제 요청 상태와 일치한다.

### MT-05: JS 없는 폼과 PRG

관련: V-24, DC-22. 선행 실행: 단계 5.

- [ ] 브라우저 설정으로 JavaScript를 끄고 액션 폼을 제출하면 303 뒤 원래 페이지에 결과가 표시된다. 새로고침해도 다시 제출되지
      않는다.
- [ ] 검증 오류가 필드별로 표시되고 `flash.input`에 지정한 필드만 값이 다시 채워진다. 비밀번호·파일은 비어 있다.
- [ ] 아주 긴 입력(수 KB)을 보내도 오류 요약은 표시되며 DevTools의 flash 쿠키가 3KB를 넘지 않는다.
- [ ] `_redirect`를 다른 origin·`//evil.example`·`javascript:`로 바꾼 폼을 직접 만들어 제출하면 같은 origin으로만 이동한다.
- [ ] 다른 origin 페이지에서 같은 액션으로 POST하는 폼을 제출하면 403이다.
- [ ] JS를 다시 켜면 같은 폼이 페이지 이동 없이 transition으로 동작하고 결과가 JS 없는 경로와 같다.

통과 기준: JS 유무와 관계없이 같은 결과이며 리다이렉트·CSRF 우회가 없다.

### MT-06: 스트리밍·취소·오류·배포 교체

관련: V-07·V-08, DC-09·DC-14. 선행 실행: 단계 4.

- [ ] 채팅 예제의 토큰 스트리밍이 끊김 없이 이어지고 긴 응답에서도 입력이 지연되지 않는다(실기기 포함).
- [ ] 스트림 도중 새 메시지를 보내면 이전 스트림이 멈추고 새 스트림만 보인다.
- [ ] 스트림 도중 네트워크를 Offline으로 바꾸면 이미 적용된 내용은 유지되고 오류가 표시된다. 자동 재실행되지 않는다.
- [ ] 결과 없는 액션(빈 성공)은 화면 변화 없이 pending만 해제된다.
- [ ] 페이지를 연 상태로 새 빌드를 배포한 뒤 액션을 실행하면 현재 URL이 문서 로드로 다시 열린다(409).
- [ ] 단건(JSON) 응답 액션과 스트림 액션의 최종 화면이 같다.

통과 기준: 취소·실패 뒤 화면이 일관되고 배포 교체가 오류 화면 없이 재로드로 처리된다.

### MT-07: 전환 애니메이션과 모션

관련: V-14, DC-06. 선행 실행: 단계 4(인페이지)·단계 6(라우터).

- [ ] 인페이지 갱신은 기본적으로 애니메이션 없이 즉시 반영되고, 스트림 중 깜빡임·클릭 막힘이 없다.
- [ ] `viewTransition` 액션(갤러리 → 상세)에서 썸네일과 상세 이미지가 모핑된다. 슬롯 첫 등장(뷰어 열기)에도 전환이 적용된다.
- [ ] 클라이언트 라우터 이동은 기본 크로스페이드, 문서 로드 이동은 CSS opt-in 크로스페이드로 비슷한 느낌이다.
- [ ] OS의 동작 줄이기(reduced motion)를 켜면 모든 전환과 `data-animate`가 생략된다.
- [ ] View Transition 미지원 브라우저(또는 기능을 끈 상태)에서 즉시 반영되고 오류가 없다.

통과 기준: 지원·미지원·reduced motion 세 조건 모두에서 DESIGN 9.1 규칙대로 보인다.

### MT-08: 클라이언트 라우터 이동

관련: V-19·V-20, DC-18·DC-20. 선행 실행: 단계 6.

- [ ] 링크·GET 폼(검색어 쿼리)·뒤로/앞으로 이동 결과가 같은 URL의 문서 로드와 같다(콘텐츠·제목·활성 메뉴).
- [ ] 뒤로 가기 시 이전 스크롤 위치가 복원되고, 해시 링크는 해당 요소로 스크롤한다.
- [ ] 새 탭 열기(수정 키·가운데 클릭)·`target`·다운로드·`data-surface-reload` 링크는 브라우저 기본 동작을 따른다.
- [ ] 없는 경로(404) 이동 시 라우터 레이아웃의 오류 페이지로 교체되고 URL이 바뀐다. 라우터 없는 페이지로는 문서 로드된다.
- [ ] 외부 사이트에 갔다가 뒤로 오면(BFCache) 화면·이벤트가 정상이고 중복 실행이 없다.
- [ ] 이동 중 다른 링크를 연타해도 마지막 링크 페이지만 남는다.
- [ ] 이동 뒤 새 페이지의 `<Boot>`와 지연 슬롯이 실행된다.

통과 기준: 모든 이동이 문서 로드와 같은 결과이고 실패 경로는 문서 로드로 대체된다.

### MT-09: persist

관련: V-21, DC-19. 선행 실행: 단계 6.

- [ ] 재생 중인 오디오 플레이어를 둔 채 여러 페이지를 이동해도 재생이 끊기지 않는다.
- [ ] persist iframe(동영상 임베드)이 이동 중 다시 로드되지 않고 재생 위치가 유지된다(`moveBefore` 지원 브라우저).
- [ ] `moveBefore` 미지원 브라우저에서는 이동은 되며, 가이드에 적힌 대로 일시 정지·재로드가 생길 수 있다(블로커 아님).
- [ ] persist 채팅 위젯의 입력 초안이 유지되고, 응답 스트림이 이동 중에도 이어진다(대상이 모두 persist인 액션).
- [ ] 다음 페이지에 짝이 없는 persist 요소는 사라지고 소리·타이머가 남지 않는다.

통과 기준: 지원 브라우저에서 상태 유실이 없고 미지원 브라우저는 문서화된 한계 안에서 동작한다.

### MT-10: prefetch

관련: V-22, DC-20. 선행 실행: 단계 6.

- [ ] 링크에 마우스를 올려 잠시 두면 HTML 요청이 한 번 나가고(`Sec-Purpose: prefetch`), 클릭 시 추가 네트워크 없이 바로 바뀐다.
- [ ] 터치 기기에서 탭할 때 prefetch가 시작되고 이동이 문서 로드보다 빠르게 느껴진다.
- [ ] Save-Data(데이터 절약 모드)나 느린 연결에서 hover·viewport prefetch가 나가지 않는다.
- [ ] 액션(로그인·언어 전환 등)을 완료한 뒤 이동하면 이전 prefetch 결과가 아닌 최신 페이지가 보인다.
- [ ] `data-prefetch="false"` 링크(로그아웃 등)는 hover해도 요청이 없다.

통과 기준: 불필요한 요청 없이 이동이 빨라지고 오래된 페이지가 보이지 않는다.

### MT-11: 지연 server 슬롯

관련: V-23, DC-21·DC-29. 선행 실행: 단계 4.

- [ ] 로그인·로그아웃 상태에서 같은 페이지의 지연 슬롯 내용이 각각 맞게 보인다. prerender 셸 페이지에서도 같다.
- [ ] Network에서 지연 요청 URL을 복사해 `p` 값을 한 글자 바꿔 열면 4xx이고 원래 페이지는 fallback을 유지한다.
- [ ] 요청 URL·응답 헤더에 props 원문이 보이지 않고, 공개 슬롯(`cache="public, …"`)만 공유 캐시 헤더를 가진다.
- [ ] 서버가 느릴 때(지연 주입) 페이지 셸은 즉시 보이고 지연 슬롯만 늦게 채워진다.

통과 기준: 셸이 막히지 않고 변조·권한 밖 요청이 거부된다.

### MT-12: 서드파티·관측 도구 기본 설치

관련: V-30·V-31, AG-09, DC-13·DC-18. 선행 실행: 단계 6. IMPLEMENT IC-10의 계정·키를 쓴다.

      `surface.page_view`)가 이동마다 한 번씩 집계되고, GTM 미리보기 모드에서 태그가 정상 실행된다.
- [ ] GTM이 동적으로 추가한 script·iframe·노드가 이동 뒤에도 남아 있고(Elements 패널), 엔진이 지우거나 중복 실행하지 않는다.
- [ ] **Sentry**(npm `init`과 CDN Loader 각각): transition·hydration·아일랜드 로드 오류가 이벤트로 수집되고 업로드한 소스맵으로

- [ ] **Datadog RUM**(npm과 CDN 비동기 스니펫 각각): 이동마다 view가 생기고 transition `fetch`가 리소스로 기록되며 session

- [ ] nonce + `'strict-dynamic'` CSP를 미들웨어로 설정한 상태에서 위 도구 설치 시 콘솔에 CSP 위반이 없다(SSR 페이지).
- [ ] 사용자 abort·abort-previous 취소는 오류로 수집되지 않는다.

통과 기준: 업체 기본 설치법 외 프레임워크 전용 설정 없이 세 도구가 문서 로드·이동 모두에서 정상 수집한다.

### MT-13: prerender·i18n·콘텐츠·이미지

- [ ] `/`에 접속하면 `lang` 쿠키 → 브라우저 언어 순으로 `/en/…`·`/ko/…`로 이동한다. 언어 전환 링크가 같은 페이지의 다른 언어로

- [ ] 히어로 이미지가 우선 로드되고(preload) 첫 화면 밖 이미지는 스크롤할 때 로드된다. DPR 2 기기와 좁은 화면에서 적절한

통과 기준: 정적 출력도 SSR과 같은 헤더·동작을 갖고 콘텐츠·이미지 품질이 기존 이상이다.
