# 서버 렌더링 슬롯과 Lithent 아일랜드 — 요구사항

작성일: 2026-10-12
상태: Idea / Draft — 논의 기록, 기능 미구현

## 문서 위치와 범위

이 문서 묶음은 StateSurface의 초기 JavaScript를 줄이면서 복잡한 클라이언트 UI를
자연스럽게 작성하는 방향을 기록한다. 사용자 요청에 따라 `docs/idea/`에 둔다.
현재 동작의 계약은 루트 [PROTOCOL.md](../../PROTOCOL.md)와
[활성 설계 문서](../ui-protocol/DESIGN.md)를 따른다.
이 초안의 제안은 현재 런타임에 구현된 API나 확정된 프로토콜이 아니다.

| 문서 | 역할 |
| --- | --- |
| [REQUIREMENTS.md](./REQUIREMENTS.md) | 목표, 범위, 제약 |
| [DESIGN.md](./DESIGN.md) | 논의 내용, 현재 구현과의 차이, 미결정 계약 |
| [IMPLEMENT.md](./IMPLEMENT.md) | 단계별 구현 후보와 테스트 게이트 |

관련 코드 범위는 `engine/client/`, `engine/server/`, `engine/shared/`, `client/`,
`routes/`, `layouts/`, `vite.config.ts`, `create-state-surface/overrides/`다.
`scaffold/`는 빌드 시 생성되므로 구현 시 원본과 overrides에서 변경해야 한다.

## 배경

현재 StateSurface는 MPA HTML을 SSR하고, 초기 상태가 있는 슬롯을 Lithent로 hydrate한다.
인페이지 변경은 서버 transition에서 생성한 NDJSON 상태 프레임을 받아 적용한다.

서버 주도 모델은 유지하되, 다음 문제를 개선하려 한다.

- 현재 페이지와 무관한 템플릿과 플러그인도 초기 클라이언트 로딩에 포함된다.
- 서버에서 출력한 설명이나 목록도 클라이언트 템플릿과 hydration을 요구한다.
- 세밀한 UI 상태와 이벤트를 슬롯 생명주기 플러그인으로 처리하면 구현 부담이 크다.
- 단건 업데이트와 스트리밍 업데이트를 명시적으로 선택하는 응답 API가 없다.

## 논의에서 정한 방향

- Next.js RSC가 주는 서버 전용 렌더링 코드 제외 효과를 `<h-state>` 경계에 적용한다.
- 작은 클라이언트 아일랜드를 두되, UI 내부에서는 Lithent 기능을 정상적인 작성 방식으로 제공한다.
- 서버는 확정 데이터와 비즈니스 처리를, 클라이언트는 상호작용 상태를 소유한다.
- `data-action`은 단순한 서버 액션의 기본 작성 방식으로 유지한다.
- 플러그인은 공통 기능과 DOM 보강을 담당하고, 복잡한 UI는 컴포넌트로 작성한다.
- 고정 HTML, 서버에서 갱신할 HTML, 클라이언트 컴포넌트를 구분하는 설계를 검토한다.

슬롯 모드 이름, 기본값, 공개 API, HTML 프레임 형식과 활성화 정책은
[DESIGN.md의 결정 목록](./DESIGN.md#8-미결정-목록)에서 추적한다.

## 제약

- 페이지 이동은 MPA, 인페이지 업데이트는 명시적인 슬롯 경계를 유지한다.
- 서버 렌더링 HTML은 애플리케이션에 등록된 템플릿에서 생성한다.
  에이전트나 외부 입력이 임의의 HTML을 생성하는 기능과 구분한다.
- 같은 DOM 내부를 서버 HTML 교체와 Lithent가 동시에 관리하지 않는다.
- 클라이언트 모듈 로딩과 서버 요청의 취소·실행 순서를 구분한다.
  기존 abort-previous 동작을 바꾸려면 별도 계약이 필요하다.
- 일반 Lithent 컴포넌트를 이벤트 시점에 hydrate하는 경로는 지연 hydration으로 기록한다.
  임의의 클로저와 반응성 연결까지 복원하는 범용 resumability로 표현하지 않는다.
- 초기 JS 총량, 실행 시간, 초기 응답 데이터와 첫 상호작용 지연을 함께 측정한다.

## 가정과 비목표

- 이번 작업 범위는 아이디어 문서화다. 런타임 구현과 릴리스는 후속 작업이다.
- React RSC/Flight 프로토콜 호환이나 Next.js로의 이전은 목표에 포함하지 않는다.
- 전체 페이지를 SPA로 바꾸거나 범용 클로저 직렬화 시스템을 만드는 작업은 포함하지 않는다.
- `client` 모드는 첫 화면의 SSR을 배제하는 의미가 아니다.
  브라우저 전용 초기화는 클라이언트 생명주기에서 수행해야 한다.
- 실제 번들 크기와 성능 절감률은 아직 측정하지 않았다.

## 호환성과 이행

기존 `defineTemplate(name, component)`에는 모드 정보가 없다.
새로운 서버 우선 작성 모델을 도입하더라도, 기존 템플릿을 자동으로 서버 전용으로
분류하면 인라인 이벤트나 클라이언트 기능이 깨질 수 있다.
기존 API의 기본 동작과 새 API의 기본값은 DC-01에서 결정한다.

서버 슬롯의 입력 데이터를 초기 `__STATE__`에서 제외하려면, 액션 실행에 필요한
메타데이터와 클라이언트 props를 별도로 정리해야 한다.
`__STATE__`는 실행할 JS가 아닌 JSON 데이터이므로, 이 감소는 초기 HTML 전송량과
파싱·메모리 비용으로 따로 측정한다.
