# 서버 렌더링 슬롯과 Lithent 아일랜드 — 수동 검증 후보

작성일: 2026-10-12
상태: Idea / Draft — 기능 구현 후 실행할 항목, 현재 미실행

요구사항은 [REQUIREMENTS.md](./REQUIREMENTS.md), 계약과 결정 ID는
[DESIGN.md](./DESIGN.md), 단계별 테스트는 [IMPLEMENT.md](./IMPLEMENT.md)에 있다.
아래 항목은 완료 보고가 아니라 구현 후 사용할 검증 기준이다.

## 실행 조건

- production build, 동일 브라우저·장치·네트워크 조건을 사용한다.
- cold cache 첫 방문과 런타임 로딩 후 반복 액션을 구분한다.
- 테스트한 commit, 경로, 렌더링 모드, 활성화 정책과 응답 형식을 기록한다.
- 모드 조합, 중첩 지원과 목표치는 해당 DC 결정에 따라 검증한다.

## MT-01: 현재 페이지에 필요한 코드

- [ ] 홈에서 가이드·채팅 템플릿, Prism과 채팅 스크롤이 초기 요청에 포함되지 않는다.
- [ ] 가이드·검색·채팅에서 필요한 청크와 CSS가 정상 로드된다.
- [ ] 디버그 비활성 상태에서는 오버레이 코드가 요청되지 않는다.
- [ ] 필요한 공통 템플릿과 오류 동작은 정상 유지된다.

통과 기준: 실제 Network 요청과 의존 청크 총량으로 불필요한 코드 제외를 확인한다.

## MT-02: static과 서버 전용 첫 화면

- [ ] static/server 콘텐츠가 해당 템플릿 JS 없이 최초 HTML에 표시된다.
- [ ] 서버 전용 페이지의 초기 entry와 첫 서버 액션에 Lithent 브리지가 포함되지 않는다.
- [ ] static 콘텐츠는 다른 슬롯의 full 갱신에도 정해진 수명대로 유지된다.
- [ ] `<details>`와 일반 링크 같은 HTML 기본 동작이 유지된다.

통과 기준: 서버 전용 슬롯의 hydration이 없고 화면과 기본 동작이 일치한다.

## MT-03: 서버 HTML 업데이트와 가이드

- [ ] 서버 액션 후 지정한 슬롯이 서버 템플릿 결과로 갱신된다.
- [ ] 언어 전환 후 본문·목차·코드 하이라이팅이 일치한다.
- [ ] 초기 및 갱신 후 Copy 버튼과 목차 스크롤이 동작한다.
- [ ] 지연 로딩된 플러그인이 정해진 생명주기로 이미 표시된 콘텐츠에 연결된다.
- [ ] 클라이언트 아일랜드에 대한 서버 DOM 소유권 규칙을 지킨다.

통과 기준: 클라이언트 본문 템플릿 없이 동작하고, DOM 관리 주체의 충돌이 없다.

## MT-04: 첫 액션과 폼 입력

- [ ] 아직 런타임이 로드되지 않은 상태에서 첫 클릭이 한 번 실행된다.
- [ ] Enter 제출과 제출 버튼의 submitter 값이 보존된다.
- [ ] 느린 로딩 중 입력을 바꿔도 실행에는 이벤트 시점에 캡처한 값을 사용한다.
- [ ] action·params·pending 대상과 BASE_PATH가 올바르게 전달된다.

통과 기준: 첫 액션이 유실·중복되지 않고 입력 스냅샷과 요청이 일치한다.

## MT-05: 활성화 트리거와 브라우저 기능

- [ ] `boot.auto` 동작이 사용자 클릭 없이 정해진 시점에 시작된다.
- [ ] 에디터 등 focus가 필요한 아일랜드가 선택한 정책대로 활성화된다.
- [ ] Clipboard처럼 사용자 활성화가 필요한 기능의 첫 실행을 확인한다.
- [ ] prefetch를 사용하면 실행 코드 활성화 시점과 전송량을 따로 기록한다.

통과 기준: 활성화 정책이 첫 동작을 방해하지 않고 무조건적인 첫 클릭 지연을 요구하지 않는다.

## MT-06: 로딩 실패, 연속 액션과 취소

- [ ] 여러 액션 중 런타임 로딩은 공유되고 액션 실행 순서는 선택한 계약을 따른다.
- [ ] 청크 로딩 실패 시 오류와 재시도 동작이 정의대로 동작한다.
- [ ] 새 transition이 이전 요청을 취소할 때 오래된 응답이 적용되지 않는다.
- [ ] 로딩·요청 실패와 취소 후 pending 표시가 남지 않는다.

통과 기준: import 완료와 요청 완료의 순서에 영향을 받지 않고 정해진 취소 정책을 유지한다.

## MT-07: 혼합 모드의 상태와 UI

- [ ] full 프레임의 슬롯 활성 집합과 제거 규칙을 확인한다.
- [ ] partial·removed·UI-only 변경이 지정한 슬롯에만 적용된다.
- [ ] 서버 accumulate가 데이터 병합 결과로 렌더링된다.
- [ ] 서버 슬롯을 초기 JSON에서 제외해도 상태 수명과 제거가 올바르다.
- [ ] 요청 내·요청 간 상태의 근거가 선택한 계약과 일치한다.

통과 기준: 기존 상태·UI 의미 또는 명시적으로 바꾼 계약이 모든 렌더링 모드에서 일관된다.

## MT-08: Lithent 로컬 상태와 생명주기

- [ ] 로컬 입력·선택·펼침과 서버 props를 같은 아일랜드에서 사용할 수 있다.
- [ ] 서버 props 갱신 중 입력 초안·선택·포커스·스크롤이 의도대로 유지된다.
- [ ] 명시적 reset과 다른 레코드·컴포넌트로의 교체가 정해진 상태 수명을 따른다.
- [ ] 제거·재활성화에서 이벤트·구독·DOM 자원 cleanup이 수행된다.
- [ ] SSR 가능한 client 컴포넌트의 첫 표시와 활성화 결과가 일치한다.

통과 기준: 일반 UI를 플러그인으로 분해하지 않고 작성하며 로컬 상태 수명이 예측 가능하다.

## MT-09: 컴포넌트 액션, 이벤트와 DOM 소유권

- [ ] 컴포넌트가 공식 API로 서버 액션을 호출하고 pending·오류·취소를 처리한다.
- [ ] 직접 핸들러와 `data-action`이 같은 이벤트를 중복 실행하지 않는다.
- [ ] 직접 이벤트 핸들러의 기본 동작 제어가 정의대로 적용된다.
- [ ] client 슬롯 내부는 Lithent가 관리하고 서버 HTML로 덮어쓰지 않는다.
- [ ] 중첩 아일랜드는 지원하는 범위에서 부모 갱신 후 상태·DOM을 유지한다.

통과 기준: 디버그 전역에 의존하지 않고 동작하며 이벤트와 DOM의 소유권이 명확하다.

## MT-10: 단건과 스트리밍

- [ ] 기존 NDJSON의 state 한 번 + done 방식이 계속 동작한다.
- [ ] 일반 JSON 응답을 Content-Type에 따라 파싱한다.
- [ ] JSON·NDJSON에서 최종 화면, 오류, 완료와 pending 해제 의미가 일치한다.
- [ ] 잘못된 본문·HTTP 오류·요청 취소가 선택한 공통 정책을 따른다.
- [ ] 서버 HTML과 클라이언트 props에 각각 단건·스트리밍을 적용해 확인한다.

통과 기준: 응답 방식과 렌더링 방식이 독립적이며 파서의 우연한 호환에 의존하지 않는다.

## MT-11: 기존 앱과 배포 호환

- [ ] 모드 없는 기존 `defineTemplate`과 `data-action`이 정해진 호환 정책을 따른다.
- [ ] 기존 SSR·초기 상태·오류 템플릿·UI 패치가 유지된다.
- [ ] BASE_PATH 배포에서 entry·동적 청크·CSS·transition 경로가 맞다.
- [ ] 원본과 overrides에서 생성한 scaffold로 새 프로젝트를 실행할 수 있다.
- [ ] 서버·클라이언트 버전 차이는 선택한 감지·호환 정책에 따라 처리된다.

통과 기준: 기존 사용자 앱과 새 scaffold가 명시된 계약대로 동작한다.

## MT-12: 성능과 체감

- [ ] 홈·가이드·검색·채팅의 실제 초기 JS raw/gzip/Brotli 총량을 전후 비교한다.
- [ ] 초기 HTML·상태 JSON 전송량과 파싱·메모리 비용을 비교한다.
- [ ] 스크립트 실행·hydration 시간과 long task를 비교한다.
- [ ] cold cache 첫 액션과 반복 액션의 pending·결과 적용 지연을 비교한다.
- [ ] 스트리밍 첫 결과 시간과 서버 렌더링 작업량을 비교한다.

통과 기준: DC-12에서 정한 목표치를 충족한다.
JS 전송 감소와 첫 액션·서버 비용의 변화가 함께 기록되어야 한다.
